# Карточка товара: Laravel + локальные LLM

Сервис собирает карточку товара из документов поставщика: PDF, DOCX и XLSX.
Каждая характеристика в ответе несёт ссылку на фрагмент, из которого она взята.
Модель работает локально через Ollama, эмбеддинги тоже локальные, внешних API нет.

Это вторая, «вдохновлённая» реализация проекта. Первая была на Python и FastAPI,
здесь тот же контракт перенесён на Laravel: очередь вместо Temporal, `laravel/ai`
вместо прямых вызовов OpenAI-совместимого клиента, Postgres + pgvector вместо
отдельного векторного хранилища.

## Что внутри

- `laravel/ai` — агенты, структурированный вывод, эмбеддинги.
- Ollama — `gemma3:4b` для генерации, `gemma3:1b` для служебных проверок,
  `bge-m3` для эмбеддингов (1024 измерения).
- Postgres 16 + pgvector: HNSW по косинусу и GIN по `tsvector('russian', …)`.
- Очередь `database`: один Job на шаг пайплайна, состояние — в `card_jobs`.
- Pest/PHPUnit, Pint.

## Пайплайн

```
POST /api/cards
      │
      ▼
   pending ──► retrieving ──► generating ──► verifying ──► critiquing
                   │              ▲              │              │
                   │              └── feedback ──┘              │
                   ▼                                            ▼
             needs_review ◄────────────────────────────► awaiting_approval
                   │                                            │
                   └────────────► approved / rejected ◄─────────┘
```

- `retrieving` — гибридный поиск (вектор + полнотекст, RRF), защита контекста.
- `generating` — структурированный ответ модели; при ошибке схемы модель
  получает текст ошибки и пробует снова.
- `verifying` — детерминированная проверка ссылок: чанк существует, был в
  контексте, а значение характеристики действительно есть в этом чанке.
- `critiquing` — второй взгляд модели. Слабая локальная модель часто шумит,
  поэтому её замечания лежат в `guard_report.critique` и не блокируют карточку:
  блокируют только схема и проверка ссылок. Это осознанное решение, а не
  недоделка.
- `awaiting_approval` / `needs_review` — человек подтверждает или отклоняет.
  Ожидание человека — это статус в БД, а не висящий Job.

Каждый переход статуса и запись результата идут в одной транзакции с
`lockForUpdate`, поэтому повторная доставка сообщения не запускает шаг дважды.
Очередь даёт at-least-once; детерминированного replay, как в Temporal, здесь нет.
Подробнее — в статье цикла и в разделе «Ограничения».

## Быстрый старт

Нужны PHP 8.4, Composer 2 и Docker.

```bash
composer install
cp .env.example .env
php artisan key:generate

docker compose up -d
docker compose exec ollama ollama pull gemma3:4b
docker compose exec ollama ollama pull gemma3:1b
docker compose exec ollama ollama pull bge-m3

php artisan migrate
php artisan serve --host=127.0.0.1 --port=8000
php artisan queue:work --tries=3 --timeout=600
```

Postgres поднимается на `127.0.0.1:5433` (порт вынесен в `PG_PORT`), Ollama — на
`127.0.0.1:11434` (`OLLAMA_PORT`). Тестовая база `card_test` создаётся init-скриптом
в `docker/postgres/init`.

Проверка:

```bash
curl http://127.0.0.1:8000/api/health/live
curl http://127.0.0.1:8000/api/health/ready
```

`/api/health/ready` возвращает версию расширения `vector`; если база или
расширение недоступны — 503.

## Демонстрационные данные

В `data/` лежат те же документы, что в Python-версии:

- `blender_passport.pdf` — паспорт блендера, две страницы с текстом;
- `blender_kp.docx` — коммерческое предложение с таблицей;
- `kettle_manual.pdf` — инструкция чайника, внутри спрятана инъекция;
- `kettle_spec.xlsx` — спецификация на три артикула;
- `boiler_scan.pdf` — скан без текстового слоя (ожидаемо `failed`);
- `golden_cards.json` — эталон для evals.

Загрузить и проиндексировать одной командой:

```bash
php artisan demo:seed
```

Она кладёт файлы в `storage/app/private/documents`, считает эмбеддинги и печатает
таблицу со статусами. `boiler_scan.pdf` ожидаемо окажется `failed`; это проверка
того, что скан без текстового слоя честно отсекается.

Через API то же самое делается по одному файлу; повторная загрузка того же
содержимого возвращает существующий `id` — дедупликация по SHA-256.

## API

| Метод | Путь | Что делает |
|---|---|---|
| `GET` | `/api/health/live` | процесс жив |
| `GET` | `/api/health/ready` | база и pgvector готовы |
| `POST` | `/api/documents` | загрузить PDF/DOCX/XLSX, вернуть `202` и `id` |
| `GET` | `/api/documents/{id}` | статус, число чанков, ошибка разбора |
| `POST` | `/api/cards` | создать задачу генерации, `202` |
| `GET` | `/api/cards/{id}` | статус, карточка, отчёт защиты |
| `POST` | `/api/cards/{id}/approve` | подтвердить |
| `POST` | `/api/cards/{id}/request-changes` | отклонить |

Создание задачи:

```bash
curl -s -X POST http://127.0.0.1:8000/api/cards \
  -H 'Content-Type: application/json' \
  -H 'Idempotency-Key: demo-1' \
  -d '{"document_ids":["01..."],"hint":"блендер погружной МиксерПро 800"}'
```

`Idempotency-Key` необязателен, но с ним повторный запрос вернёт ту же задачу.

## Документы и чанки

- PDF — `smalot/pdfparser`; сканы без текстового слоя дают `failed` с понятной
  причиной, OCR в базовый путь не входит.
- DOCX — `phpoffice/phpword`, таблицы превращаются в отдельные чанки.
- XLSX — `phpoffice/phpspreadsheet`, по чанку на строку с артикулом.
- Нормализация: лигатуры, мягкие переносы, повторяющиеся колонтитулы, пробелы.
- Чанки: около 900 символов с перекрытием 180, таблицы не рвутся по словам.

## Поиск

`ChunkRepository::hybrid()` делает два списка кандидатов: векторный (HNSW,
косинус, порог `SEARCH_MIN_SIMILARITY`) и полнотекстовый (`plainto_tsquery`,
русская морфология). Списки сливаются по RRF, поэтому случайный промах одного
канала не убивает выдачу. Порог отсекает шум: на эталонном наборе релевантные
фрагменты дают заметно больший скор, чем соседние.

## Защита

- Персональные данные маскируются до отправки в модель: телефоны, email,
  номера карт (проверка Луна), ИНН (контрольные суммы). Метки вида `[PHONE_1]`
  остаются в контексте и в ответе.
- Инъекции ищутся двумя слоями: регулярные правила и модель-детектор. Детектор
  при недоступности отвечает «подозрительно» (fail-closed).
- Если правило сработало, из чанка вырезаются подозрительные предложения;
  остаток остаётся, если в нём есть смысл. Чанк целиком исключается, когда
  после вырезания ничего не осталось или детектор подозревает текст без
  конкретного предложения. Если таких чанков больше `SUSPICIOUS_CHUNK_LIMIT`
  или контекст опустел — задача уходит в `needs_review`.
- Ответ модели ещё раз проверяется на утечку PII и следы служебных инструкций.
  При замечаниях — до трёх попыток перегенерации.

## Ссылки

Контекст отдаётся модели с короткими метками:

```
[S1 | 01M5... | passport.pdf | стр. 1 | Характеристики]
Мощность 800 Вт
```

Модель возвращает `characteristics` массивом объектов:

```json
{"name": "Мощность", "value": "800 Вт", "chunk_id": "S1", "page": 1}
```

Сервис сам разворачивает `S1` в настоящий `chunk_id` и проверяет три вещи:

1. чанк есть в базе;
2. чанк был в контексте, который реально получила модель;
3. значение характеристики встречается в тексте этого чанка.

Третья проверка ловит выдуманные значения, которые модель приписала соседнему
фрагменту. Если проверка не прошла, генератор получает список ошибок и пробует
снова; после трёх попыток задача падает, а не уходит человеку с неверными
ссылками.

## Деньги

Каждый вызов модели пишется в `llm_calls`: модель, роль, токены, длительность и
стоимость в целых микроединицах. Тариф учебный, локальные модели «бесплатны»,
но учёт нужен, чтобы сравнивать шаги и закладывать бюджет при переезде на
внешний API.

```bash
php artisan costs:report
php artisan costs:report --job=01...
```

## Evals

```bash
php artisan evals:run          # два документа по умолчанию
php artisan evals:run --all    # все документы из golden_cards.json
php artisan evals:run --document=kettle_manual.pdf
```

Считаются три метрики: совпадение характеристик с эталоном, подтверждение
цитат (значение и страница) и вердикт судьи. Отчёт сохраняется в
`storage/app/private/evals/`. Судья — та же слабая `gemma3:1b`, поэтому его
вердикт стоит читать как сигнал, а не как приговор.

## Тесты

```bash
php artisan test
```

Тесты идут только против Postgres (`card_test`): в SQLite нет `vector` и
русского полнотекстового поиска. AI и очередь в тестах подменяются, сеть не
нужна.

## Ограничения

- Нет OCR: сканы без текстового слоя не индексируются.
- Нет авторизации и мультитенантности: это демонстрационный сервис, а не SaaS.
- Очередь `database` не даёт Temporal-подобного детерминированного replay.
  Повторная доставка безопасна за счёт статусов и транзакций, но побочные
  эффекты вроде повторного вызова модели возможны; для продакшена нужен
  идемпотентный ключ на уровне шага.
- Локальные модели на CPU медленные: одна карточка — минуты, не секунды.
- Критик на `gemma3:1b` ненадёжен и оставлен совещательным.
